# บทที่ 1 บทนำ

## 1.1 ที่มาและความสำคัญ

อาคารวิทยวิภาส (SC09) ของวิทยาลัยการคอมพิวเตอร์ มหาวิทยาลัยขอนแก่น มีห้องหลายประเภท ทั้งห้องบรรยาย ห้องปฏิบัติการคอมพิวเตอร์ ห้องประชุม และห้องโถงอเนกประสงค์ ซึ่งนักศึกษา อาจารย์ และเจ้าหน้าที่ต้องการใช้สำหรับการเรียนการสอน ติวสอบ ประชุมโครงงาน และกิจกรรมต่าง ๆ

ปัญหาที่พบคือผู้ใช้ไม่รู้ว่าห้องไหนว่างในช่วงเวลาที่ต้องการ ต้องสอบถามเจ้าหน้าที่หรือเดินไปดูหน้าห้อง การจองผ่านช่องทางที่ไม่เป็นระบบทำให้เกิดการจองซ้อนกัน ไม่มีหลักฐานการอนุมัติ และไม่รู้ว่าห้องถูกปิดซ่อมเมื่อไร ระบบจองห้องของคณะที่มีอยู่แล้ว (ระบบจองห้องเรียนคณะวิทยาศาสตร์) ใช้กับอาคารของคณะวิทยาศาสตร์ ไม่ครอบคลุมห้องของอาคาร SC09 และไม่มีกฎที่ต่างกันตามบทบาทผู้ใช้

กลุ่มจึงพัฒนา **ระบบจองห้องอาคาร SC09 (SC09 Room Booking)** เป็นเว็บแอปพลิเคชันที่ให้ผู้ใช้ค้นหาห้องว่างตามวัน เวลา ความจุ และอุปกรณ์ ส่งคำขอจองที่ระบบตรวจกฎและเวลาชนให้อัตโนมัติ ให้เจ้าหน้าที่อนุมัติ จัดการห้อง และดูสถิติ พร้อมแจ้งเตือนผู้เกี่ยวข้องทุกครั้งที่สถานะการจองเปลี่ยน โครงงานนี้เป็นส่วนหนึ่งของรายวิชา CP353002 Principles of Software Design and Development จึงเน้นการออกแบบตามหลัก SOLID และการใช้ Design Pattern ที่เหมาะกับปัญหาจริง

## 1.2 วัตถุประสงค์

1. เพื่อพัฒนาเว็บแอปพลิเคชันสำหรับค้นหาและจองห้องในอาคาร SC09 ที่ป้องกันการจองเวลาชนกันได้ แม้มีผู้ใช้ส่งคำขอพร้อมกัน
2. เพื่อให้ระบบบังคับใช้กฎการจองที่ต่างกันตามบทบาท (นักศึกษา อาจารย์ เจ้าหน้าที่ ผู้ดูแลระบบ) และมีขั้นตอนอนุมัติที่ตรวจสอบย้อนหลังได้
3. เพื่อแจ้งเตือนผู้เกี่ยวข้องอัตโนมัติเมื่อมีคำขอใหม่หรือสถานะการจองเปลี่ยน
4. เพื่อฝึกออกแบบซอฟต์แวร์ตามหลัก SOLID และประยุกต์ใช้ Design Pattern (Strategy, Chain of Responsibility, State, Observer)
5. เพื่อฝึกกระบวนการพัฒนาเป็นทีม ได้แก่ Git workflow, Pull Request + Code Review, การทดสอบอัตโนมัติ, CI/CD และการ deploy ขึ้นระบบคลาวด์

## 1.3 ขอบเขตของโครงงาน

### 1.3.1 ผู้ใช้ระบบ

| ผู้ใช้ | สิ่งที่ทำได้ |
|---|---|
| ผู้เยี่ยมชม (ยังไม่ login) | สมัครสมาชิก เข้าสู่ระบบ ดูรายการห้อง ค้นหาห้องว่าง อ่านคู่มือ |
| นักศึกษา | จองห้อง (ต้องรออนุมัติ) ดู ลบคำขอ ยกเลิก check-in การจองของตัวเอง ดูตารางการใช้ห้อง รับแจ้งเตือน แก้โปรไฟล์ |
| อาจารย์ | ทำได้เหมือนนักศึกษา แต่การจองอนุมัติอัตโนมัติ และจองได้นานและล่วงหน้ามากกว่า |
| เจ้าหน้าที่ | อนุมัติหรือปฏิเสธคำขอ จัดการห้อง ประเภทห้อง อุปกรณ์ ช่วงปิดห้อง ผู้ใช้ และดูสถิติ |
| ผู้ดูแลระบบ | ทำได้ทุกอย่างของเจ้าหน้าที่ |

### 1.3.2 ฟังก์ชันของระบบ

1. **ผู้ใช้และการยืนยันตัวตน:** สมัครสมาชิก (เฉพาะนักศึกษาและอาจารย์) เข้าสู่ระบบด้วย JWT โปรไฟล์ จัดการผู้ใช้ (เปลี่ยนบทบาท ปิด/เปิดใช้งาน)
2. **ห้องและอุปกรณ์ (CRUD Resource ที่ 1):** เพิ่ม แก้ไข ลบ (ห้องเป็นการปิดใช้งาน) ห้อง ประเภทห้อง และอุปกรณ์ ค้นหาด้วยคำค้น กรองตามชั้น ประเภท ความจุ อุปกรณ์ เรียงลำดับและแบ่งหน้า ความสัมพันธ์ห้องกับอุปกรณ์แบบ Many-to-Many พร้อมจำนวน ค้นหาห้องว่าง และกำหนดช่วงปิดห้อง
3. **การจอง (CRUD Resource ที่ 2):** สร้าง ดู ลบคำขอ ตรวจกฎ 5 ขั้น (เวลา กฎตามบทบาท ห้อง ช่วงปิด เวลาชน) ตารางห้องรายวัน และตารางการใช้ห้องทั้งอาคาร (ปฏิทินรายเดือน + ตารางรวมทุกห้อง)
4. **วงจรสถานะการจอง:** อนุมัติ ปฏิเสธ (ต้องมีเหตุผล) ยกเลิก check-in จบการใช้งาน ประวัติการเปลี่ยนสถานะ และ Scheduler บันทึกไม่มาใช้ห้องและปิดการจองอัตโนมัติทุก 1 นาที
5. **แจ้งเตือนและสถิติ:** แจ้งเตือนในระบบ (กระดิ่ง + หน้ารายการ) อ่าน/ลบแจ้งเตือน และแดชบอร์ดสถิติการจองตามสถานะและชั่วโมงใช้งานต่อห้อง
6. **คู่มือการใช้งาน:** หน้าอธิบายขั้นตอน กฎ และสถานะ

### 1.3.3 ขอบเขตข้อมูลและข้อจำกัด

- ครอบคลุมเฉพาะห้องในอาคาร SC09 จำนวน 16 ห้อง บนชั้น 1, 2, 4, 5 และ 6
- ความจุและอุปกรณ์ของห้องเป็นค่าที่ทีมรวบรวมจากผังอาคาร
- จองได้เฉพาะเวลาเปิดอาคาร 08:00–22:00 น. และภายในวันเดียว
- แจ้งเตือนเฉพาะในระบบ ยังไม่ส่งอีเมลหรือ LINE
- ยังไม่รองรับการจองแบบซ้ำทุกสัปดาห์ และการแก้ไขการจองผ่านหน้าเว็บ (มี API แล้ว)

## 1.4 ประโยชน์ที่คาดว่าจะได้รับ

1. ผู้ใช้ค้นหาห้องว่างและจองได้เองตลอด 24 ชั่วโมง ไม่ต้องติดต่อเจ้าหน้าที่
2. ไม่มีการจองซ้อนกัน เพราะระบบตรวจเวลาชนและควบคุมคำขอที่มาพร้อมกัน
3. เจ้าหน้าที่มีคิวอนุมัติ ประวัติการเปลี่ยนสถานะ และสถิติการใช้ห้องสำหรับวางแผน
4. ผู้ใช้รู้ผลการอนุมัติทันทีผ่านแจ้งเตือน และระบบปิดการจองที่ไม่มาใช้อัตโนมัติ ทำให้ห้องว่างให้คนอื่น
5. ทีมได้ประสบการณ์ออกแบบซอฟต์แวร์ที่ขยายต่อได้ และกระบวนการพัฒนาแบบมืออาชีพ

## 1.7 นิยามศัพท์

| คำศัพท์ | ความหมาย |
|---|---|
| การจองที่ยังใช้งาน (Active booking) | การจองสถานะ รออนุมัติ (PENDING) อนุมัติแล้ว (APPROVED) หรือกำลังใช้ห้อง (CHECKED_IN) ใช้ตรวจเวลาชนและนับโควตา |
| เวลาชน | การจองห้องเดียวกันที่ช่วงเวลาซ้อนกัน คือ เริ่ม < เวลาสิ้นสุดของอีกรายการ และ สิ้นสุด > เวลาเริ่มของอีกรายการ (ต่อกันพอดีไม่ถือว่าชน) |
| ช่วงปิดห้อง (Closure) | ช่วงเวลาที่เจ้าหน้าที่ปิดห้อง เช่น ซ่อมบำรุง จองไม่ได้ |
| Check-in | การยืนยันว่ามาใช้ห้องจริง ทำได้ตั้งแต่ 15 นาทีก่อนถึง 15 นาทีหลังเวลาเริ่ม |
| ไม่มาใช้ห้อง (No-show) | การจองที่อนุมัติแล้วแต่ไม่ check-in ภายใน 15 นาทีหลังเวลาเริ่ม |
| JWT | JSON Web Token ใช้ยืนยันตัวตนแบบไม่เก็บ session ฝั่ง server |
| Migration | ไฟล์ SQL ที่สร้างและเปลี่ยนโครงสร้างฐานข้อมูลตามลำดับเวอร์ชัน (Flyway) |
| CI/CD | การ build และทดสอบอัตโนมัติทุกครั้งที่ส่งโค้ด (CI) และ deploy อัตโนมัติ (CD) |
| Pessimistic Lock | การล็อกแถวในฐานข้อมูล (`SELECT ... FOR UPDATE`) ให้คำขออื่นรอจน transaction แรกเสร็จ |
