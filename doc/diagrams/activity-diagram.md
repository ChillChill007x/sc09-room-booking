# Activity Diagrams

## 1. กระบวนการจองห้องตั้งแต่ต้นจนจบ

แยกช่องตามผู้กระทำ (swimlane) ด้วย subgraph

```mermaid
flowchart TB
    subgraph USER["ผู้จอง (นักศึกษา)"]
        A1([เริ่ม]) --> A2[เข้าสู่ระบบ]
        A2 --> A3[ค้นหาห้องว่าง หรือดูตารางการใช้ห้อง]
        A3 --> A4[เลือกห้องและกรอกฟอร์มจอง]
        A4 --> A5[ส่งคำขอ]
        A9[แก้ข้อมูลตามข้อความ error] --> A4
        A12[ได้รับแจ้งเตือนว่าอนุมัติแล้ว]
        A18[ได้รับแจ้งเตือนว่าถูกปฏิเสธ<br/>พร้อมเหตุผล]
        A13{ยังต้องการใช้ห้อง?}
        A14[ยกเลิกการจอง]
        A15[มาที่ห้องและ check-in<br/>ภายใน 15 นาทีก่อนถึงหลังเวลาเริ่ม]
        A16[ใช้ห้อง]
        A17[กดจบการใช้งาน]
    end

    subgraph SYS["ระบบ"]
        S1[ล็อกแถวผู้ใช้และห้อง]
        S2{ตรวจกฎผ่านทั้ง 5 ขั้น?}
        S3[บันทึกการจอง สถานะ PENDING<br/>+ ประวัติสถานะ]
        S4[แจ้งเตือนเจ้าหน้าที่ทุกคน]
        S8[เปลี่ยนเป็น APPROVED<br/>+ ประวัติ + แจ้งเตือนผู้จอง]
        S9[เปลี่ยนเป็น REJECTED สถานะสิ้นสุด<br/>+ ประวัติ + แจ้งเตือนผู้จอง]
        S10{check-in ทันเวลา?}
        S11[CHECKED_IN]
        S12[Scheduler: NO_SHOW<br/>+ แจ้งเตือนผู้จอง]
        S13[Scheduler: COMPLETED<br/>เมื่อเลยเวลาสิ้นสุด]
        S14[CANCELLED + แจ้งเตือน]
        S15[COMPLETED]
    end

    subgraph STAFF["เจ้าหน้าที่"]
        T1[เปิดคิวอนุมัติ]
        T2{อนุมัติ?}
        T3[อนุมัติ]
        T4[ปฏิเสธพร้อมเหตุผล]
    end

    A5 --> S1 --> S2
    S2 -- ไม่ผ่าน --> A9
    S2 -- ผ่าน --> S3 --> S4 --> T1 --> T2
    T2 -- ใช่ --> T3 --> S8
    T2 -- ไม่ --> T4 --> S9 --> A18 --> E1([จบ])
    S8 --> A12 --> A13
    A13 -- ไม่ --> A14 --> S14 --> E1([จบ])
    A13 -- ใช่ --> S10
    S10 -- ไม่ทัน --> S12 --> E1
    S10 -- ทัน --> A15 --> S11 --> A16
    A16 --> A17 --> S15 --> E1
    A16 -. ไม่กดจบ .-> S13 --> E1
```

กรณีอาจารย์ เจ้าหน้าที่ และผู้ดูแลระบบ ขั้น "บันทึกการจอง" จะได้สถานะ APPROVED ทันที (ข้ามคิวอนุมัติ) เพราะ `requiresApproval()` ของ policy เป็น false ส่วนกรณีถูกปฏิเสธ การจองเป็น REJECTED ซึ่งเป็นสถานะสิ้นสุด กระบวนการจบหลังผู้จองได้รับแจ้งเตือน (ถ้ายังต้องการห้องให้ส่งคำขอใหม่) มีเพียงการจองที่ APPROVED เท่านั้นที่ไปต่อขั้น check-in

## 2. การตรวจกฎการจอง (Chain of Responsibility)

```mermaid
flowchart TB
    start([รับ BookingRequest]) --> lock[ล็อกแถวผู้ใช้ แล้วล็อกแถวห้อง]
    lock --> h1["<b>ขั้นที่ 1: TimeRangeHandler</b><br/>เริ่มก่อนสิ้นสุด, ไม่ใช่เวลาที่ผ่านมาแล้ว,<br/>เริ่มและจบวันเดียวกัน, อยู่ใน 08:00-22:00"]
    h1 --> d1{ผ่าน?}
    d1 -- ไม่ --> e1["400 เวลาเริ่มต้องมาก่อนเวลาสิ้นสุด /<br/>จองเวลาที่ผ่านมาแล้วไม่ได้ /<br/>ต้องจบในวันเดียวกัน / นอกเวลาเปิดอาคาร"]
    d1 -- ใช่ --> h2["<b>ขั้นที่ 2: PolicyHandler (Strategy ตาม role)</b><br/>ระยะเวลา ≤ ชม.สูงสุด, ล่วงหน้า ≤ N วัน,<br/>การจองค้าง < โควตา"]
    h2 --> d2{ผ่าน?}
    d2 -- ไม่ --> e2["400 เกินชั่วโมงสูงสุด /<br/>เกินจำนวนวันล่วงหน้า /<br/>การจองค้างครบโควตา"]
    d2 -- ใช่ --> h3["<b>ขั้นที่ 3: RoomHandler</b><br/>พบห้อง, ห้อง ACTIVE,<br/>จำนวนคน ≤ ความจุ"]
    h3 --> d3{ผ่าน?}
    d3 -- ไม่ --> e3["404 ไม่พบห้อง /<br/>400 ห้องไม่เปิดให้จอง /<br/>400 เกินความจุ"]
    d3 -- ใช่ --> h4["<b>ขั้นที่ 4: ClosureHandler</b><br/>ไม่มีช่วงปิดห้องทับ"]
    h4 --> d4{ผ่าน?}
    d4 -- ไม่ --> e4["409 ห้องปิดใช้งานในช่วงเวลาที่เลือก"]
    d4 -- ใช่ --> h5["<b>ขั้นที่ 5: ConflictHandler</b><br/>ไม่มีการจองที่ยังใช้งานทับ"]
    h5 --> d5{ผ่าน?}
    d5 -- ไม่ --> e5["409 ช่วงเวลานี้มีการจองห้องนี้แล้ว"]
    d5 -- ใช่ --> ok([ผ่าน: บันทึกการจอง])
```

ตรวจกฎที่ไม่ต้องใช้ฐานข้อมูลก่อน (ขั้น 1–2 บางส่วน) แล้วค่อย query เพื่อตัดคำขอที่ผิดกฎชัดเจนออกเร็วที่สุด

## 3. การอนุมัติคำขอของเจ้าหน้าที่

```mermaid
flowchart TB
    s([เปิดคิวอนุมัติ]) --> list[ระบบแสดงรายการ PENDING เรียงตามเวลาเริ่ม หน้าละ 10]
    list --> pick[เลือกคำขอ]
    pick --> d{ตัดสินใจ}
    d -- อนุมัติ --> lockA[ล็อกแถวการจอง]
    d -- ปฏิเสธ --> reason{กรอกเหตุผลแล้ว?}
    reason -- ไม่ --> warn[ปุ่มปฏิเสธกดไม่ได้ / 400] --> reason
    reason -- ใช่ --> lockR[ล็อกแถวการจอง]
    lockA --> st{ยังเป็น PENDING?}
    lockR --> st2{ยังเป็น PENDING?}
    st -- ไม่ --> conflict[409 สถานะเปลี่ยนไปแล้ว]
    st2 -- ไม่ --> conflict
    st -- ใช่ --> time{ก่อนเวลาเริ่ม?}
    time -- ไม่ --> late[400 เลยเวลาเริ่มแล้ว]
    time -- ใช่ --> room{ห้อง ACTIVE และไม่มีช่วงปิดทับ?}
    room -- ไม่ --> roomErr[400 / 409 ห้องใช้ไม่ได้]
    room -- ใช่ --> approved[APPROVED + ประวัติ]
    st2 -- ใช่ --> rejected[REJECTED + ประวัติ + เหตุผล]
    approved --> notify[หลัง commit แจ้งเตือนผู้จอง]
    rejected --> notify
    notify --> reload[รายการหายจากคิว<br/>ถ้าหน้าว่างถอยไปหน้าก่อนหน้า]
    reload --> e([จบ])
```
