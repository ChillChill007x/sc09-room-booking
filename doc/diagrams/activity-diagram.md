# Activity Diagrams

## 1. กระบวนการจองห้องตั้งแต่ต้นจนจบ

แยกช่องตามผู้กระทำ (swimlane) ด้วย subgraph

```mermaid
flowchart TB
    subgraph USER["ผู้จอง (นักศึกษา)"]
        A1([เริ่ม]) --> A2[เข้าสู่ระบบ]
        A2 --> A3[ค้นหาห้องว่าง หรือดูตารางการใช้ห้อง]
        A3 --> A4[เลือกห้องและกรอกฟอร์มจอง]
        A4 --> A5[ส่งคำขอ]
        A9[แก้ข้อมูลตามข้อความ error] --> A4
        A12[ได้รับแจ้งเตือนผลการอนุมัติ]
        A13{ยังต้องการใช้ห้อง?}
        A14[ยกเลิกการจอง]
        A15[มาที่ห้องและ check-in<br/>ภายใน 15 นาทีก่อนถึงหลังเวลาเริ่ม]
        A16[ใช้ห้อง]
        A17[กดจบการใช้งาน]
    end

    subgraph SYS["ระบบ"]
        S1[ล็อกแถวผู้ใช้และห้อง]
        S2{ตรวจกฎผ่านทั้ง 5 ขั้น?}
        S3[บันทึกการจอง สถานะ PENDING<br/>+ ประวัติสถานะ]
        S4[แจ้งเตือนเจ้าหน้าที่ทุกคน]
        S8[เปลี่ยนเป็น APPROVED หรือ REJECTED<br/>+ แจ้งเตือนผู้จอง]
        S10{check-in ทันเวลา?}
        S11[CHECKED_IN]
        S12[Scheduler: NO_SHOW<br/>+ แจ้งเตือนผู้จอง]
        S13[Scheduler: COMPLETED<br/>เมื่อเลยเวลาสิ้นสุด]
        S14[CANCELLED + แจ้งเตือน]
        S15[COMPLETED]
    end

    subgraph STAFF["เจ้าหน้าที่"]
        T1[เปิดคิวอนุมัติ]
        T2{อนุมัติ?}
        T3[อนุมัติ]
        T4[ปฏิเสธพร้อมเหตุผล]
    end

    A5 --> S1 --> S2
    S2 -- ไม่ผ่าน --> A9
    S2 -- ผ่าน --> S3 --> S4 --> T1 --> T2
    T2 -- ใช่ --> T3 --> S8
    T2 -- ไม่ --> T4 --> S8
    S8 --> A12 --> A13
    A13 -- ไม่ --> A14 --> S14 --> E1([จบ])
    A13 -- ใช่ --> S10
    S10 -- ไม่ทัน --> S12 --> E1
    S10 -- ทัน --> A15 --> S11 --> A16
    A16 --> A17 --> S15 --> E1
    A16 -. ไม่กดจบ .-> S13 --> E1
```

กรณีอาจารย์ เจ้าหน้าที่ และผู้ดูแลระบบ ขั้น "บันทึกการจอง" จะได้สถานะ APPROVED ทันที (ข้ามคิวอนุมัติ) เพราะ `requiresApproval()` ของ policy เป็น false ส่วนกรณีถูกปฏิเสธ ผู้จองจบที่ "ได้รับแจ้งเตือน" และจองใหม่ได้

## 2. การตรวจกฎการจอง (Chain of Responsibility)

```mermaid
flowchart TB
    start([รับ BookingRequest]) --> lock[ล็อกแถวผู้ใช้ แล้วล็อกแถวห้อง]
    lock --> h1

    subgraph h1["1. TimeRangeHandler"]
        t1{เริ่มก่อนสิ้นสุด?} -- ไม่ --> e1[400 เวลาเริ่มต้องมาก่อนเวลาสิ้นสุด]
        t1 -- ใช่ --> t2{ไม่ใช่เวลาที่ผ่านมาแล้ว?}
        t2 -- ไม่ --> e2[400 ไม่สามารถจองเวลาที่ผ่านมาแล้ว]
        t2 -- ใช่ --> t3{เริ่มและจบวันเดียวกัน?}
        t3 -- ไม่ --> e3[400 การจองต้องเริ่มและจบในวันเดียวกัน]
        t3 -- ใช่ --> t4{อยู่ใน 08:00-22:00?}
        t4 -- ไม่ --> e4[400 จองได้เฉพาะเวลาเปิดอาคาร]
    end

    t4 -- ใช่ --> h2
    subgraph h2["2. PolicyHandler (Strategy ตาม role)"]
        p1{ระยะเวลา ≤ ชม.สูงสุด?} -- ไม่ --> e5[400 จองได้ครั้งละไม่เกิน N ชั่วโมง]
        p1 -- ใช่ --> p2{ล่วงหน้า ≤ N วัน?}
        p2 -- ไม่ --> e6[400 จองล่วงหน้าได้ไม่เกิน N วัน]
        p2 -- ใช่ --> p3{การจองค้าง < โควตา?}
        p3 -- ไม่ --> e7[400 มีการจองที่ยังไม่สิ้นสุดครบ N รายการแล้ว]
    end

    p3 -- ใช่ --> h3
    subgraph h3["3. RoomHandler"]
        r1{พบห้อง?} -- ไม่ --> e8[404 ไม่พบห้อง]
        r1 -- ใช่ --> r2{ห้อง ACTIVE?}
        r2 -- ไม่ --> e9[400 ห้องไม่เปิดให้จอง]
        r2 -- ใช่ --> r3{จำนวนคน ≤ ความจุ?}
        r3 -- ไม่ --> e10[400 ห้องรับได้ N คน]
    end

    r3 -- ใช่ --> h4
    subgraph h4["4. ClosureHandler"]
        c1{มีช่วงปิดห้องทับ?} -- มี --> e11[409 ห้องปิดใช้งานในช่วงเวลาที่เลือก]
    end

    c1 -- ไม่มี --> h5
    subgraph h5["5. ConflictHandler"]
        f1{มีการจองที่ยังใช้งานทับ?} -- มี --> e12[409 ช่วงเวลานี้มีการจองห้องนี้แล้ว]
    end

    f1 -- ไม่มี --> ok([ผ่าน: บันทึกการจอง])
```

ตรวจกฎที่ไม่ต้องใช้ฐานข้อมูลก่อน (ขั้น 1–2 บางส่วน) แล้วค่อย query เพื่อตัดคำขอที่ผิดกฎชัดเจนออกเร็วที่สุด

## 3. การอนุมัติคำขอของเจ้าหน้าที่

```mermaid
flowchart TB
    s([เปิดคิวอนุมัติ]) --> list[ระบบแสดงรายการ PENDING เรียงตามเวลาเริ่ม หน้าละ 10]
    list --> pick[เลือกคำขอ]
    pick --> d{ตัดสินใจ}
    d -- อนุมัติ --> lockA[ล็อกแถวการจอง]
    d -- ปฏิเสธ --> reason{กรอกเหตุผลแล้ว?}
    reason -- ไม่ --> warn[ปุ่มปฏิเสธกดไม่ได้ / 400] --> reason
    reason -- ใช่ --> lockR[ล็อกแถวการจอง]
    lockA --> st{ยังเป็น PENDING?}
    lockR --> st2{ยังเป็น PENDING?}
    st -- ไม่ --> conflict[409 สถานะเปลี่ยนไปแล้ว]
    st2 -- ไม่ --> conflict
    st -- ใช่ --> time{ก่อนเวลาเริ่ม?}
    time -- ไม่ --> late[400 เลยเวลาเริ่มแล้ว]
    time -- ใช่ --> room{ห้อง ACTIVE และไม่มีช่วงปิดทับ?}
    room -- ไม่ --> roomErr[400 / 409 ห้องใช้ไม่ได้]
    room -- ใช่ --> approved[APPROVED + ประวัติ]
    st2 -- ใช่ --> rejected[REJECTED + ประวัติ + เหตุผล]
    approved --> notify[หลัง commit แจ้งเตือนผู้จอง]
    rejected --> notify
    notify --> reload[รายการหายจากคิว<br/>ถ้าหน้าว่างถอยไปหน้าก่อนหน้า]
    reload --> e([จบ])
```
